# 第7回：発展機能7項目

目標：各機能について「誰が操作し、どこへ保存し、何を制限するか」を説明する。

## 実コードと流れ

| 機能 | コードで追う場所 | 説明する要点 |
| --- | --- | --- |
| A ログイン | auth.js、users・user_sessions | パスワードハッシュ、Session、ログアウト時の失効 |
| B 投稿者権限 | app.jsの編集・削除 | req.userと所有者比較、SQLでもuser_idを条件にする |
| C ベストアンサー | POST /questions/:id/best-answer、best_answers | 質問者のみ、1質問1件、別質問の回答を拒否 |
| D いいね | POST /questions/:id/answers/:answerId/like、answer_likes | 回答ID・ユーザーIDの複合主キー、追加・取消、重複防止 |
| E 高度な検索 | GET /questions | 状態絞り込みと回答件数順の両方 |
| F 通知 | 回答POST、/notificationsの各ルート | 他人の回答を質問者へ通知、宛先制限、既読・未読 |
| G 解決状態 | POST /questions/:id/status、questions.status | 初期未解決、質問者による双方向変更、一覧・詳細表示 |

[app.js](../../app.js)・[auth.js](../../auth.js)・[db/schema.sql](../../db/schema.sql) を開いて、表の処理を検索する。

回答保存は `BEGIN` → 回答INSERT → 通知INSERT → `COMMIT`。失敗時は `ROLLBACK` し、片方だけ保存されることを防ぐ。これがトランザクション。
ベストアンサーの選択と解決状態の変更は独立しており、選択で自動的に解決済みにはならない。
自分の回答では通知を作らない。通知の未読件数は画面遷移や再読み込み時に更新する。
質問・回答・通知は20件ずつ。通知や回答操作後は対象回答があるページへ移動する。
