# ChatGPT・Codex共通：ここから再開

共有リポジトリ：`Yocchanika-Dev/toiro-qa`／**学習ブランチ：`study-notes`**。
教材のコード照合基準は `0c389f9`。最新の学習地点は [PROGRESS.md](PROGRESS.md) だけで管理する。
チャット履歴の自動同期は前提にしない。Gitの最新記録を読み、終了時に保存して引き継ぐ。

## 開始時

1. `study-notes` の最新コミットを取得する。mainや検索結果の古いキャッシュで代用しない。
2. [PROGRESS.md](PROGRESS.md) → [README.md](README.md) → 該当回の教材 → 該当コードの順に読む。
3. 読んだブランチ・コミット（取得できなければその旨）・進捗リビジョン・次の一問を短く示す。
4. 次の問題を一問だけ出し、本人の回答を待つ。説明済み・AIテスト済みを本人理解済みと扱わない。

Codexでの取得例（未コミット変更がある場合は切り替え前に内容を確認する）：

```sh
git status --short --branch
git fetch origin
git switch study-notes
git pull --ff-only origin study-notes
git rev-parse HEAD
```

作業ツリーに変更があれば、勝手に破棄・stash・上書きしない。別チャットが更新中なら同時編集せず、片方の保存を待ってから最新へ追従する。

## GitHubを読めない場合

読むことも書くことも、各チャットの実際の接続・権限で確認する。未確認の機能を「利用可能」と決めつけない。
URLを読めなければ、Codexで `npm run learning:pack` を実行し、生成された `.local/learning-handoff.md` をChatGPTへ添付する。
これは許可リストにある教材・コード・進捗だけをまとめる。環境変数や会話全文は含めない。未コミット変更があれば、その内容も含む作業時点のスナップショットになる。
ファイルには生成元コミットと進捗リビジョンがある。Gitへ反映されていない持ち帰り記録があれば、その記録も先に照合する。

## 学習終了時／切り替える前

1. [SESSION_TEMPLATE.md](SESSION_TEMPLATE.md) で今回の回答・確認結果・残る疑問・次の一問を整理する。
2. 書き込み可能なら最新リモートを再取得し、開始時のコミットと比較。別更新があれば、両方の記録を読んで統合する。force pushしない。
3. 公開できる匿名の技術記録だけを `sessions/日時-短い識別子.md` として追加する。
4. `PROGRESS.md` の現在地・次の一問・最終記録リンク・リビジョンを更新する。リビジョンは現在値の次（例：learning-0002）。過去の回答記録は残す。
5. 教材修正と学習記録を別Commitで保存し、`study-notes` へPushする。変更ファイルを限定し、秘密情報と差分を確認する。
6. GitHubで保存後のコミットと進捗を読み直す。最終返信で保存先・コミット・次回の一問を示す。

**書けない場合は、終了テンプレートを埋めたMarkdownを返す。** ユーザーがその返答をCodexへ貼れば、Codexは元コミット・リビジョンと最新進捗を比較して取り込む。チャット内に返しただけなら「Git未保存」と明記する。
正答を示しただけ・教材を整備しただけでは、学習を完了にしない。本人操作も根拠がある範囲だけ記録する。

## 公開・運用上の境界

公開してよい内容は教材・匿名の技術的回答・学習状態のみ。氏名・メール・パスワード・Cookie・個人的な会話は保存しない。公開進捗自体が不要なら、以降の回答記録はGitへ載せず持ち帰りファイルで管理する。
既存質問19〜21と質問19の回答2件は保持。本人操作には今回作成した専用データを使う。
学習ブランチの自動デプロイ停止は `vercel.json` に記録する。mainへマージ・本番再デプロイ・DB変更は学習記録更新に含めない。
ローカルのREQUIREMENTS.mdが課題条件の基準。外部向けの提出要点は [第8回](08-submission.md) にある。
